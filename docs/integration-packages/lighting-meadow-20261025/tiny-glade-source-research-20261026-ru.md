# Tiny Glade: подтверждённые источники и направление реализации

26.10.2026. Пользователь уточнил основной ориентир: максимально приблизить свет
и шейдеры к Tiny Glade, включая поиск доступного исходного кода. Искались
официальные материалы и репозитории авторов; чужие фан-проекты не считаются
исходниками игры. Полного опубликованного renderer source Tiny Glade в проверенных
источниках не найдено. Это результат поиска, а не доказательство его отсутствия.

В этом проходе проверены официальная ссылка, название и описание; видео полностью не транскрибировано, детали не выдаются за просмотренные. |

Туман переведён на froxels с локальными источниками, растительность тоже обновлена. Следовательно, доклад2024 не описывает всю актуальную версию2026. |

Из этих материалов следует инженерный ориентир для нас: свет должен зависеть
от окружающей геометрии, в том числе вне кадра. Одни SSAO/палитра/размытие не
создают переноса освещения. Это наш вывод о реализации Little Castle, не цитата
или точное воспроизведение алгоритма Pounce Light.

## Открытый код авторов

1. [EmbarkStudios/kajiya](https://github.com/EmbarkStudios/kajiya) и
   [обзор GI](https://github.com/EmbarkStudios/kajiya/blob/main/docs/gi-overview.md).
   Томаш [сам связывает](https://h3.gd/) эту работу с собой. Репозиторий Rust/Vulkan,
   MIT/Apache-2.0, с HLSL и экспериментальными динамическими GI/cache решениями.
   С июня2026 архивирован, автор предупреждает, что больше его не поддерживает.
   Это самостоятельный исследовательский renderer, не исходный код Tiny Glade
   и не готовый URP-плагин. Изучать различие direct/indirect, запросы к irradiance
   cache и борьбу с light leaks; не переносить весь ReSTIR/hardware-RT stack ради
   одного эффекта. Стоимость из чужого README не является нашей оценкой GPU.

   Конкретные точки входа в [assets/shaders/ircache](https://github.com/EmbarkStudios/kajiya/tree/main/assets/shaders/ircache):
   `lookup.hlsl`, `ircache_grid.hlsl`, `trace_irradiance.rgen.hlsl`,
   `trace_accessibility.rgen.hlsl`, `sum_up_irradiance.hlsl`,
   `ircache_validate.rgen.hlsl`. Наличие файлов проверено через GitHub API;
   полный аудит каждого алгоритма ещё не выполнен.

2. [h3r2tic/raymarch.hlsl](https://gist.github.com/h3r2tic/9c8356bdaefbe80b1a22ae0aaee192db).
   Публичный код Томаша для depth-buffer ray marching, contact shadows, SSGI/SSR.
   MIT/Apache-2.0 указаны в заголовке. Это подходящий конкретный shader reference
   для проверки screen-space пересечений и толщины; его зависимые include и
   соглашения матриц/глубины нужно адаптировать к URP и reversed-Z. Screen-space
   путь не закрывает требование отражения от объектов вне кадра. Код в LC пока
   не скопирован; при адаптации сохранить авторство и выбранную лицензию.

3. [anopara/country-slice](https://github.com/anopara/country-slice).
   Публичный MIT-прототип Анастасии Опары на Rust/Bevy ECS/OpenGL.
   [Папка shaders](https://github.com/anopara/country-slice/tree/main/shaders)
   содержит instanced_wall, shadow, terrain, path-mask и compute размещения кирпичей.
   Полезен для раннего procedural/instancing подхода и материала стен.
   Его README называет проект небольшим hobby toy; нельзя представлять его
   нынешним движком Tiny Glade или готовым современным GI. В lighting-копию
   исходники не подключались.

## Следующий ограниченный эксперимент в Little Castle

Совместный Meadow baseline и восемь настоящих замеров уже есть. Следующую сцену
делать отдельно, сохраняя его как контроль, а не заменяя художественную картинку
непроверенной GI-системой. Не требуется менять Unity/URP или инструменты карты.

Первый тест: пол/земля, светлая стена, тонкая крыша, открытая и закрытая области,
один цветной отражатель вне кадра. Для непрямого света — упрощённые поверхности,
ограниченное мировое поле, несколько направлений/проб и один отражённый вклад.
Исключить individual blades/leaves из дорогого представления. Трассировку по
простым препятствиям и кеш проверять отдельно от полного mesh ray tracing.
Это предлагаемый путь эксперимента, не заявление, что Tiny Glade устроен точно так.

На уровне shared LC-контракта spatial indirect должен заменять соответствующую
часть hemisphere ambient, затем получать единый material/screen AO; direct,
transmission и emission остаются отдельно. Не добавлять постоянный зелёный tint
вместо отражения: цветовой вклад зависит от света на источнике и видимости.

Связь с уже существующим редактором: MapEditSession.Changed, preview=false,
world XZ bounds, локальная очередь dirty tiles с ограниченным halo. Проверять
revision/собственный epoch перед публикацией результатов. Высота и новые
препятствия требуют будущего согласованного расширения kinds; сейчас есть
Surface|Decoration. Полный локальный контракт — local-cache-invalidation-ru.md.

Критерии решения после реализации: темнее под крышей; отражённый цвет на стене;
эффект от объекта вне кадра не исчезает при повороте; тонкая стена не пропускает
свет; снос/Undo локально обновляют кеш без полного пересчёта. Измерять отдельно
CPU-update, uploads, GPU, stale-work rejection и время сходимости. Только после
этого выбирать постоянную архитектуру и ADR. Копирование большого renderer без
такого теста не доказывает совпадения со светом Tiny Glade.

Дальнейший порядок: пространственный свет → устойчивость теней на движущейся
камере → согласованные ночные источники → высотный/объёмный туман. Материалы,
нормали и художественная форма дубов/стен также влияют на результат; они должны
оцениваться на реальных игровых моделях, не только на LUT или цвете солнца.
