# Parity roadmap — Tiny Glade inspiration vs Little Castle implementation

## Проверенные публичные ориентиры

В сентябре 2026 Pounce Light сообщил, что Tiny Glade перешёл на froxel-подход для participating media и смог учитывать локальные фонари внутри тумана. В том же месяце разработчики рассказали об упрощённом ray-traced indirect lighting, работающем на старых устройствах. Публично описаны также особые карты теней для объёмного света.

Эти описания не являются открытым исходным кодом и не дают гарантии, что мы можем или должны повторять закрытую архитектуру строчка в строчку.

## Реальное состояние первой ветки

| Возможность | Сейчас | Для более близкого результата |
|---|---|---|
| Дальний туман | depth-aware ray marching | более стабильные границы и aerial perspective |
| Туман в низинах | высотная экспонента | зависимость от рельефа/реки, ветер/погода |
| Локальный туман | максимум 4 сферы | поля плотности мирового масштаба |
| Цвет дня и ночи | через текущий контроллер | подбор по эталонным кадрам |
| Мягкий солнечный glow | приближённый scattering | реальная проверка затенения солнца |
| Лучи между деревьями | нет | shadowed volumetric scattering |
| Свет фонарей внутри тумана | до 4 бюджетных Point Light, затухание без теней | полноценное injection local lights into froxels |
| Косвенный свет на стенах | существующая stylized-имитация | dynamic GI research/implementation |
| Четыре биома | фокус камеры + один priority zone | интеграция реальных полей биомов |
| Производительность | ручное число шагов | upscaling, temporal reprojection, GPU budgets |
| Качество | код без запуска Unity | компиляция, кадры, багфикс, профилирование |

## Этап A: заставить прототип достоверно работать

- Открыть Unity и проверить shader compile, Inspector, Resources material, PlayMode.
- Исправить реальные платформенные depth/UV и прозрачность, убрать полосатость лучевого интегрирования.
- Проверить старые шейдеры, ветер и ночное освещение.
- Ввести минимальные smoke-tests на время суток, переключение биома и дополнительных камер.
- Измерить GPU ms при 8/12/16/24 шагах (включая дальнюю стратегическую камеру).

Это обязательные действия до merge. Статус: НЕ ПРОВЕРЕНО В РЕДАКТОРЕ.

## Этап B: художественное качество для карты Little Castle

- World-space river distance field из MacroWorldPlan для локальной дымки вдоль двух рек.
- Маски высоты/влажности и климатических биомов без разрыва чанков.
- Автоматический zoom fade (чем дальше камера, тем выше приоритет читаемости).
- Сглаженное смешивание нескольких макрозон и отдельных высотных уровней.
- Визуализация debug-проходов: raw depth, density, transmittance, lighting.
- Низкое разрешение fog buffer + depth-aware upscaling, если дешевле.
- Проверка леса, снега и эльфийской растительности при обилии foliage alpha-cutouts.

## Этап C: настоящий объёмный свет

Для достижения эффекта света сквозь деревья и под горными скалами:

1. Исследовать переход к froxel 3D-grid: экранные тайлы X/Y + неравномерно распределённая глубина Z.
2. Хранить в сетке extinction/scattering; поддержать height fog, локальные density volumes и мировые маски рек.
3. В каждой ячейке собрать текущий directional sun/moon и максимум N **бюджетных** локальных источников света.
4. Добавить directional shadow attenuation через корректные каскады/карты теней. Проверить, что тени качающихся деревьев совпадают с геометрией.
5. Выполнить front-to-back интеграцию, bilateral upsample с использованием depth, temporal reprojection и reset при резких перемещениях камеры.
6. Не превращать каждое освещённое окно в Point Light; сохранять существующую Tier 0/1/2 модель NightLightBudgetManager.
7. Тестировать на 2/8/16 игроках, дальнем зуме и нагрузке на GPU.

Это новая существенная система. Перед её реализацией сравнить техническую стоимость на Built-in с отдельно измеренным URP-переходом. Если URP действительно выигрывает — оформить новый ADR, ветку миграции, конверсию текущих материалов и ShadowCaster.

## Этап D: мягкие тени и динамический непрямой свет

- Приоритет — художественный light transport: мягкие тени, читаемые контакты, тёплые окна и холодная ночь.
- Изучить probe solutions, screen-space GI, упрощённые voxel/BVH-прокси, spherical harmonics и динамические позиции построек.
- Unity baked GI не будет автоматически учитывать здания, которые игрок строит во время матча.
- Не копировать код закрытых рендереров; использовать собственные математические реализации или аудит лицензий сторонних открытых библиотек.
- Проверить Gamma vs Linear отдельно на тех же материалах (никакого автоматического преобразования).

## Что считать выполнением

Оценка должна проводиться по набору **одинаковых тестовых кадров**: утро/полдень/закат/ночь; горы, река, хвойный лес, эльфийские деревья, снежный биом, дома/стены/фонари; ближняя и дальняя камера. Отмечать форму тумана, световые лучи, цвет, стабильность при движении, доступность построек/юнитов/дорог и GPU ms.

Точная идентичность движка Tiny Glade НЕ является требованием; требование — сравнимая художественная выразительность при приемлемой производительности стратегии. Первый коммит не доказывает визуального паритета.
