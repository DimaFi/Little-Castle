# Следующий визуальный проход водопада — запрос пользователя 02.11.2026

Отложенная задача. Пользователь просит закончить текущий checkpoint, а эту работу
выполнить **потом**. Сейчас геометрия/шейдер водопада ради этого запроса не меняются.

## Что исправить

1. Переходы река → верхний край водопада и водопад → принимающая река.
   На пользовательском кадре видны резкая прямоугольная граница верхней воды,
   различие двух поверхностей и слишком яркая белая кромка/полосы. Проверить
   сопряжение по всей ширине, боковые стыки, толщину и нижний выход. Сечение,
   уровень и направление должны согласовываться с текущим руслом. Исключить
   щели, наложенные плоскости, z-fighting, видимый торцевой прямоугольник и
   необоснованно резкую полосу на спокойном входе.
2. Сделать цвет водопада максимально похожим на текущую воду. Сохранить общую
   палитру мелкой/глубокой воды и связь с освещением/временем суток. Проверить
   отдельно pigment, отражения и пену: белая пена не должна маскировать цвет
   всей водной массы. Уже существующее общее окрашивание этапа C не считается
   доказательством художественного совпадения на этом ракурсе.
3. Уменьшить силу ярких продольных полос. Предпочтительно дать автору карты
   понятные настройки, доступные **при создании карты**, а затем в World Editor.
   Настройка только скрытого материала/отладочного компонента недостаточна.

## Настройки для проектирования следующего прохода

- По умолчанию наследовать цвет основной воды; опциональный локальный tint и
  сила смешивания для отдельного водопада.
- Яркость/интенсивность полос и пены, контраст, покрытие/плотность, мягкость
  границы и масштаб рисунка. Основной ползунок яркости должен позволять почти
  убрать полосы; текущую чрезмерную белизну не брать обязательным минимумом.
- Раздельные параметры для потока, верхнего стыка, промежуточных уступов,
  нижней пены и брызг, с наследованием общего профиля.
- Общий профиль карты и локальное переопределение, сброс к наследованию,
  видимый preview. Указать единицы, диапазоны, defaults и влияние на стоимость.
- Использовать существующие профили воды и единый presentation clock. Будущее
  хранение настроек в карте должно сохранять совместимость v10/v11 и более
  старых сохранений; не записывать ссылки на transient materials в данные мира.
