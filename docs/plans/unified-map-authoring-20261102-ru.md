# Единое создание и редактирование карт

Пользователь подтвердил реализацию 02.11.2026. Сейчас интерфейс размещается
в Unity, позднее те же операции будут доступны разработчику и игроку в игре.

## Архитектура

Источник данных — MapAuthoringDocument и MapEditSession. Runtime-слой содержит
валидацию, создание карты, команды редактирования, историю и сериализуемые данные.
Он не зависит от UnityEditor, EditorWindow, AssetDatabase, файловых диалогов или
конкретных кнопок. UnityEngine-типы существующего документа допустимы: цель —
встроенный игровой редактор, не перенос на другой движок.

Unity-окно — адаптер: собирает параметры, вызывает общую операцию и показывает
ошибку. Создание scene/assets, диалоги сохранения и SceneView остаются в Editor.
Будущий игровой UI заменит этот адаптер, а не перепишет правила карты. Файловое
хранилище игрового редактора также потребует собственного адаптера вместо
AssetDatabase. Нельзя выдавать текущий Editor asset workflow за готовую систему
обмена пользовательскими картами.

Не добавлять второй документ земли/рек для генератора или отдельные игровые
правила в обработчики GUI. Горы и декоративная граница должны иметь явный
контракт с реальной высотой и игровой областью.

## Этапы

1. Изолированная ровная карта выбранного размера: собственный ID, source,
   материалы, ground mesh и сцена; общая runtime-фабрика и Unity-мастер.
   Существующие кисти, JSON и проверка текущего документа в Game.
2. Проверить сохранение/повторное открытие, дальний угол, Undo/Redo, Game,
   разрешение масок/земли и стоимость разных размеров. Не менять основную карту.
3. Подключить процедурный рельеф как начальный документ. Повторная генерация
   сначала создаёт отдельный вариант; не уничтожает ручную работу молча.
4. Подключить существующие горы/границы, сначала один сектор, затем периметр.
   Художественные улучшения: GitHub issue90; дождь/гроза: issue89.
5. Отдельно создать runtime UI и хранилище пользовательских карт поверх тех же
   операций. Доработать размещение, роли, лимиты и упаковку разрешённых ресурсов.

## Ограничения первой версии

Размер задаётся до создания: изменение Bounds готовой карты не является resize.
Начальный диапазон 32–512 м по каждой стороне с решёткой высот 1 м — технический
лимит прототипа, не обещание одинаковой производительности. Маска покрытия
существующего редактора 512×512; её физическая детализация зависит от размера.
Сначала пустая основа: нельзя копировать authored растения основной карты ради
вида луга. Сгенерированную траву/декор подключать отдельно с корректными bounds.

До проверки в Unity не считать новый путь готовым для пользователя. Проверки
модели и компиляции не доказывают вид, Game UI, rendering или сохранение сцены.
Непроверенный дым PR88 не импортировать. Незавершённый верхний стык водопада
остается отдельным набором изменений и не должен попасть в коммит этого этапа.
