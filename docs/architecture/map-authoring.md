# Общая основа ручного редактора карты

Состояние на 26.10.2026, этапы покрытия, рельефа и деревьев. Рабочая копия — Little-Castle_URP_20261024.
Канонический порядок этапов находится в основном проекте:
`docs/plans/map-authoring-and-lighting-coordination-20261025-ru.md`.

## Данные и команды

`MapAuthoringDocument` — сериализуемая основа ручной карты: версия схемы,
mapId, ревизия базы, границы X/Z, версия правил декоративного размещения,
упорядоченное покрытие, MapHeightFieldData, конечные MapTreeInstance и области
исключения размещения. Это авторская часть существующего мира.
`SurfacePaintData` остаётся совместимым адаптером существующего Unity-ассета Meadow.

`MapEditSession` владеет копиями базы, правок и текущего мазка. Оба интерфейса
используют BeginStroke / AppendPoint / CommitStroke или AddStroke. Текущий мазок
виден в QuerySurface, но до Commit не входит в сохранение. Один мазок — одна
команда истории. ClearEdits также отменяется одной командой. Новая команда
после Undo очищает Redo; после загрузки история начинается заново.
История хранит добавленные/удалённые записи, не снимок всей карты на каждый мазок.
Результаты запросов и экспорта — копии; интерфейс не может обойти команды,
изменив список точек снаружи.

MapEditAccess задаёт доступ к Road / Meadow / Erase / Terrain и операциям деревьев. Проверяется при добавлении,
завершении мазка, Undo / Redo и очистке. Загрузка доверенного состояния с диска
восстанавливает карту независимо от доступных сейчас инструментов. Это пока
локальная политика, не серверная авторизация. Настройки интерфейса не заменяют
эти проверки. Отключение роли не позволяет менять карту через старую историю.

Проверяются уникальные ID базы и дельты, версия документа, конечность чисел,
границы карты, радиус 0.1–8 м, сила/плотность 0–1, профиль и ограничения размера
списков. Ошибка загрузки сохраняет прежнюю карту и историю.

Существующие `SurfacePaintStroke`, `ToRoadData()`, `WorldRoadData` и
`ChunkTerrainVertexMasks.DistanceToSegment/SoftCorridor` переиспользованы.
ToRoadData задаёт стабильный FNV ID и центральную линию положительного дорожного
мазка. Текущее покрытие остаётся декоративным: это ещё не строительство дороги,
не обновление MacroWorldPlan, не стоимость пути и не навигация. Стирание травы
не удаляет дорожку; луг перекрывает видимую дорожку согласно прежнему алгоритму.

## Сохранение

`MapEditSave` v3 содержит mapId, ревизию/отпечаток базы, упорядоченные правки
покрытия и итоговые изменённые узлы высоты. V1/v2 покрытия импортируются.
`WorldSaveState.mapEdits` — опциональная точка подключения к существующему
корню сохранения. Старые сохранения мира не требуют авторской карты.
`StoreIn()` завершает текущую транзакцию перед записью.

Игровой Meadow сохраняет `meadow-map-edits-v3.json` в persistentDataPath:
временный файл → замена с .bak. Старые `meadow-map-edits-v2.json` и
`meadow-surface-edits-v1.json` не перезаписываются и используются по очереди
при отсутствии v3. Самый старый формат не имеет
идентичности базы, поэтому его импорт допускается только после проверки данных
в текущих границах. V2 проверяется по точному прежнему расположению полей базы,
без нового поля высот; v3 проверяет и базовую сетку высот. Другая карта,
ревизия или отпечаток отвергаются.
JSON не содержит текстур, материалов, мешей или Unity Object references.

Авторский JSON хранит полную MapAuthoringDocument. В окне разработчика можно
сохранить/открыть файл или явно применить его к SurfacePaintData и существующей
маске предпросмотра. Применение увеличивает ревизию: старые v2-дельты после
смены базы требуют явной миграции, автоматически к другой базе не прикладываются.
Сцена при этом не пересоздаётся и не сохраняется окном автоматически.

## Локальная инвалидация

Пространственный индекс мазков использует существующий ChunkCoordinate, ячейку
32 м и мировые координаты, включая отрицательные. QuerySurface возвращает
локальные записи в исходном порядке. Обычный Undo удаляет мазок из его ячеек,
не перестраивает индекс всей карты.

MapRegionChange сообщает мировую область, Surface/Decoration и признак preview.
Preview нужен для отображения во время движения; дорогие зависимые кеши могут
ждать preview=false. Это будущий интерфейс для локальных кешей света,
коллизии/навигации, а не вызов полного пересчёта карты на каждой точке.

`SurfacePaintRasterizer` — единый алгоритм авторской и игровой маски.
`MapSurfaceTileCache` лениво создаёт только запрошенные 32-метровые CPU-плитки,
обновляет только затронутые резидентные плитки и позволяет их освобождать.
Каждая плитка имеет по одному дополнительному texel с каждой стороны:
пограничные центры выборок совпадают с соседней плиткой, а инвалидация включает
эти края. `MapSurfaceGpuCache` держит отдельные RG16-текстуры только для запрошенных
плиток и отдаёт готовые MaterialPropertyBlock для terrain/grass draw-групп.
При изменении обновляются GPU-текстуры затронутых резидентных плиток; Release
освобождает одновременно CPU/GPU-данные. При 128 внутренних texels это
130×130×2 байт на плитку без mipmaps, а не текстура всей карты.
В тесте карта 65536×65536 м сохраняет две резидентные плитки после удалённого
мазка. Высоты/меши/коллизии всей карты ради этого не создаются.

Существующий Meadow-адаптер сохраняет 512² RG16 для участка 96×104 м,
чтобы сохранить визуальную совместимость без правки шейдеров. Он переигрывает
только dirty rectangle; GPU получает отдельный прямоугольник через staging
texture + CopyTexture. При отсутствии поддержки CopyTexture остаётся полный
upload с явным regionalGpuUpload=false. CPU остаётся источником значений:
GPU-копирование не гарантирует актуальность CPU-данных Texture2D.GetRawTextureData.

Scatter пересчитывает кандидатов только в затронутых областях 32 м. Готовые
8-метровые patches остальных областей переиспользуются. Матрицы общих пакетов
рисования растут только при нехватке ёмкости; диагноз placementDigest считается
лениво. Для подсчёта/рисования остаётся проход по метаданным резидентных patches.
Бюджет maximumInstances теперь относится к одной области 32 м, а не ко всей
карте: локальный мазок больше не вытесняет удалённые экземпляры глобальным top-N.
Это изменение нужно учитывать при сравнении больших заполненных участков.

Плотная трава, цветы и мелочь сейчас декоративны, без отдельного игрового
состояния/коллайдеров. Смена библиотеки может изменить производный декор;
версия правил закреплена в документе, но фиксация итоговых значимых экземпляров
и каталогов относится к этапу объектов/деревьев. Нельзя превратить текущий
scatter в интерактивные ресурсы без устойчивых instance ID и отдельного состояния.

## Интерфейсы и границы первого этапа

Игровая панель Meadow: луг / дорожка / убрать траву, радиус, сила покрытия,
плотность мелочи, Mixed / Flowers / ForestFloor, Undo / Redo, Save / Load.
Ctrl+Z / Ctrl+Y работают при включённой кисти. Панель прокручивается по высоте;
переход указателя в UI завершает мазок, поэтому под UI он не продолжается.

`Little Castle → Map → Surface Authoring`: выбор базы, SceneView-кисть,
те же параметры и история, авторский JSON, явное применение к базе.
На земле и траве временная маска видна через MaterialPropertyBlock;
предыдущие блоки восстанавливаются при закрытии окна/входе в Play Mode.
Общие материалы, шейдеры и свет для предпросмотра не редактируются.
Scatter предпросматривается в Player; окно показывает маску и покрытие.

Этот этап не превращает исследовательский Meadow в готовый стример полной
карты. Большому миру ещё нужны сами резидентные terrain/grass views и вызовы
Get/Release готового GPU-кеша из их жизненного цикла. Одна draw-группа должна
относиться к одной плитке: смешивать в ней траву разных плиток нельзя.
Огромную Texture2D вместо этого создавать нельзя. Существующий интерфейс
_SurfacePaint/_SurfacePaintBounds пригоден для отдельных draw-групп;
новые шейдерные изменения на этом этапе не потребовались.

Следующий этап: Oak A/B/C/D с итоговыми сохраняемыми instance records, затем реки.

## Рельеф, этап 2

`MapHeightFieldData` — мировая решётка с origin/spacing, нижней/верхней границей,
базовым уровнем, разреженными базовыми блоками 16×16 samples и защищёнными Rect.
Один узел принадлежит одному блоку; соседние terrain views читают те же мировые
узлы. Правки — конечные значения отдельных узлов поверх базы, не команды
с зависящим от кадров Time.deltaTime. Нет Unity Object references.

`MapHeightField` использует ту же диагональ треугольников, что существующий
terrain mesh. Высота опор растения совпадает с треугольниками земли, а нормали
вычисляются в общей мировой решётке с соседними выборками. Поэтому разные
views не создают собственные несовпадающие высоты/нормали на стыках.

`BeginHeightStroke(radius, deltaPerStamp)` / `AppendHeightPoint` / `CommitStroke`
обслуживают оба интерфейса. Плавный край, clamp к пределам базы, MapEditAccess.Terrain,
один мазок в общей истории с покрытием. Undo/Redo/Cancel/Clear/Save/Load работают
со смешанной историей. При отзыве доступа текущий preview откатывается.
Защищённые области расширяются на шаг решётки при выборе изменяемых узлов,
чтобы прилегающие треугольники не деформировали защищённый участок.

В Meadow исходная земля — регулярная решётка 193×193 с шагом 200/192 м.
`MeadowSurfacePainter.CreateDocument` читает её существующие вершины, если у
SurfacePaintData нет явного `hasHeightBase`. Этот marker обязателен: Unity
может создать пустой экземпляр нового serializable class в старом ассете.
Без marker нельзя считать такой пустой экземпляр авторской плоской картой.
Исходный меш и ассет при импорте не меняются. Авторский ExportMap запекает
текущие конечные высоты в plain-data базу. Явное применение в Editor сохраняет
heightField и hasHeightBase. V3 после смены базы требует миграции, как и покрытие.

`MapTerrainPresentation` — disposable представление существующего регулярного
меша. Совпадение мировых решёток проверяется до изменения сцены. Mesh views
разделяются по 16×16 исходных ячеек; в Meadow это 144 небольших view на прежнюю
визуальную подложку 200×200 м. Правка перестраивает только затронутые views.
Это ограниченный Meadow-адаптер, не создание всех чанков большой игровой карты.
Большой мир должен создавать только резидентные views по тому же контракту.

Коллизия имеет отдельные меши: изменение визуального меша не требует готовить
коллизию автоматически на каждый preview. FlushColliderBudget(2) выполняется
одним владельцем view раз в кадр. Объект не создаётся на каждую травинку.
Навигационной системы/NavMesh в текущем стенде нет; для неё доступен тот же
MapRegionChange.Height с bounds/preview, без фиктивного полного bake карты.

Native grass использует временную копию данных представления, прежние общие
LOD meshes и материалы. Только затронутые patches меняют матрицы, наклон и bounds;
исходные матрицы служат постоянной точкой отсчёта, поэтому отмена не накапливает
дрейф. Импортированные акценты перепроецируются по Y. Scatter получает тот же
SampleHeight и пересобирает местные области. Существующие ground-level LODGroup
служат временными опорами деревьев/предметов, сохраняя исходный offset и вертикаль.
Это не заменяет сохраняемые object records будущего каталога деревьев.
Дорожка остаётся маской на самой деформируемой земле; отдельный плавающий меш
дорожки не вводится. Тестовый движущийся объект также читает новую поверхность.

В игровом UI добавлены «Поднять землю» / «Опустить землю», радиус до32 м,
скорость 0.1–4 м/с и отображение пределов. В SceneView те же команды с частотой
15 stamps/s. Автор может задать пределы документа: существующие значения должны
помещаться в диапазон. Это изменение базы, после него история начинается заново;
применение к ассету остаётся отдельной явной кнопкой. -4…12 м — пробные пределы
этого масштаба Meadow, не утверждённые ограничения производственных карт.

Закрытие/сохранение сцены, вход в Play и уничтожение владельца восстанавливают
источники мешей, matrices, tree transforms, renderer/collider state и property
blocks. Перед сохранением сцены Editor save guard убирает временные views,
после сохранения подключает preview снова. Изменений света/URP-профилей нет.

Текущая точность травы — опора и касательная плоскость целого пучка. На очень
резких выпуклостях отдельные корни внутри пучка могут расходиться с поверхностью.
Для строгого прилипания каждого blade-root потребуется общий height sampling
в grass shader с одинаковым учётом в visible/depth/shadow/normals passes.
Это запрос для последующей интеграции, а не изменение общих шейдеров во время
параллельной работы со светом. Сглаживание, выравнивание и вертикальные обрывы
в этом этапе не добавлены.

## Деревья: общие записи, каталоги и представление (этап 3)

`MapTreeInstance` — конечная авторитетная запись: stableId, archetypeId,
catalogVersion, X/Z, yaw, scale, groundOffset, clearanceRadius и playerEditable.
Y вычисляется из той же MapHeightField, что земля. `ToWorldSpawn` адаптирует запись
к существующему WorldSpawnData. В данных нет prefab, материалов и GameObject.

Частичный MapEditSession.Trees обслуживает PlaceTree, TransformTree, DeleteTree,
BeginTreeBrush/AppendTreeBrush и общие Commit/Cancel/Undo/Redo/Clear/Save/Load.
Кисть создаёт конечные записи одной командой. Ячейки, jitter, выбор источника,
поворот и масштаб выводятся из стабильных входов; итог сохраняется, а не
генерируется заново при загрузке. Одинаковый seed не разрешает наслаивать
повторные экземпляры в занятом месте. Spatial index 32 м ограничивает запросы
соседей и области представления. Проверяются границы, склон, интервалы между
стволами, существующая дорожная маска и placementExclusions (резерв/будущая вода).
Это геометрические ограничения размещения, не будущая игровая экономика.

Сохранение v4 содержит overrides и tombstones относительно базовых деревьев.
Clear возвращает авторскую базу; удаление исходного дерева сохраняется tombstone.
Миграция v2/v3 проверяет прежний fingerprint и сохраняет импортированную базу
деревьев. Веса пака и новые версии каталога не перетасовывают готовую композицию.
Запись неизвестного источника сохраняется; её view отсутствует до подключения
совместимого prefab. Изменение самой базы по-прежнему требует миграции saves.

`MapTreeCatalog` — расширяемый ScriptableObject: entries (определение, prefab,
превью, localBounds) и weighted packs. Стартовый Resources/MapAuthoring/
MeadowTreeCatalog содержит утверждённые Oak A/B/C/D и авторский pack oak.abcd.
Ensure не перезаписывает существующий каталог. Добавление пака/entry выполняется
в ассете со стабильными ID. После подключения нового prefab выполнить
Little Castle/Map/Refresh Tree Catalog Bounds. Проверенный Player с -treeChecks
рендерит реальные модели в TreePreviews; Import Verified Oak Thumbnails импортирует
карточки без смены глобального света. Для новых ID имя PNG строится из stable ID.

MapEditAccess.TreePlace/TreeEdit/TreeBrush и Author проверяются в общем слое.
Определения задают playerPlaceable/authorOnly, паки — authorOnly; instance хранит
снимок playerEditable. Player preset разрешает одиночное размещение/редактирование
разрешённых деревьев; авторская кисть недоступна. Права можно настроить; UI не
заменяет проверки команд. Это локальный механизм доступа, не сетевая защита.

`MapTreePresentation` скрывает прежние шесть Oak-источников Meadow и создаёт
временные views по данным. Импорт старой сцены выполняется один раз через
Meadow-адаптер имён prefab, с детерминированными ID и исходными offsets;
hasTreeBase отличает явную пустую базу от ещё не импортированного legacy-ассета.
Сохраняются существующие shared materials, mesh и три авторских LOD.
Нет отдельного Update на каждом дереве. Сейчас бюджет: радиус 120 м, максимум
96 резидентных views, до 8 новых за кадр, простые коллайдеры стволов до 28 м.
Это ограниченное prefab-представление для текущего стенда; леса большой карты
потребуют дальнего instanced/impostor представления и отдельного профилирования.

Локальные Objects/Height события обновляют только затронутые опоры, без смены
ID и пересоздания view при переносе/масштабе. Выбор использует локальный
эллипсоид кроны и узкий объём ствола после грубого bounds-теста, не точный
силуэт каждого листа. Перед сохранением сцены и при Dispose исходные деревья
восстанавливаются; временные объекты имеют DontSave. Editor и Player используют
одни команды: галерея, одиночная посадка, кисть пака, выбор, перенос, поворот,
масштаб и удаление. Ручная UX-приёмка мышью в открытом пользовательском Player
не выполнялась, чтобы сохранить его правки.

Следующий этап — реки разработчика: русло, вода, берега и камни с будущими
бродами, горными истоками и водопадами. Общие шейдеры, свет и URP-профили не менялись.
