## Доработка предпросмотра (полировка, без интеграции)

Новая ветка **не изменяет никакие файлы, которые существовали в checkpoint**: изменяются только ранее добавленные специально для firefly-preview файлы. Публичная ветка основного проекта, речной этап B, освещение, редактор и данные сохранений остаются нетронутыми. Сам original preview тоже не переписывался.

- **Поведение:** в URP-шейдере огоньки имеют стабильные по позиции типы полёта: зависание, медленный дрейф и мягкий подъём/петля; фазы мерцания отличаются.
- **Визуал:** ядро и приглушённый ореол; вдалеке интенсивность плавно падает. Для вновь созданной cell — fade-in около 0.9 с.
- **Distance LOD:** настраиваемые start/end как доли радиуса камеры, минимум дальних частиц. Частицы перемешаны фиксированным seeded Fisher–Yates внутри cell, поэтому сокращение количества не обрезает половину участка. LOD дискретный по числу инстансов, плавного per-instance crossfade между уровнями пока **нет** — проверить popping при движении камеры.
- **FPS protection:** отдельный feedback-контроллер без аллокаций, opt-in; target 30–144 FPS, min scale 0.2–0.9, hysteresis/EMA. **Работает только в Play Mode для Game-камеры и обрабатывает не более одного замера за кадр.** Понижает бюджет world/near, а не радиус (нет массовой перестройки cell); не меняет глобальные QualitySettings, URP asset, vSync и игровой FPS cap. Не гарантирует заданный FPS, т.к. кадр может тормозить по другим причинам.
- **Плотная тест-зона:** в окне появились «Добавить плотную тест-зону» / «Удалить тест-зону»: локальный эллипс 18×14 м, 100 / 100 м², отдельный high-priority ID, тёплый цвет. Добавляется и удаляется **только** в preview-профиле; операция поддерживает Undo, остальные зоны не удаляются. После тестов удалить вручную или Undo.
- **Диагностика:** видны world/submitted, LOD cull, пропуски по бюджету, масштаб auto-контроллера; fps-цифры в редакторском SceneView отсутствуют, это намеренно.
- **Тесты:** добавлены EditMode NUnit для монотонности LOD, feedback controller (снижение, восстановление, границы), валидации и density test-zone. Нужен фактический прогон Unity.

**Процедура:** сначала проверить версию с автоматикой OFF и Low/Medium/High при двух высотах камеры. Затем включить auto protection на отдельном **Play Mode** тестовом объекте со ссылкой на профиль: в обычном EditorWindow временный объект умышленно удаляется при переходе в Play, чтобы не повредить текущую игровую сцену. После этого в Unity Profiler сравнить p95/p99 frame time и GC Alloc, стресс-зону и плавность движения на порогах LOD. Оценка «120 FPS» только по Editor не принимается.

## Как завтра открыть визуальный preview в Unity

1. Открыть отдельный worktree в **Unity 6000.5 / URP 17.5**. Сначала убедиться, что проект компилируется; `main` и checkpoint рек не трогать.
2. Меню **Little Castle → Atmosphere → Firefly Preview (Isolated)**.
3. Нажать **«Создать профиль»** и выбрать путь для нового экспериментального `.asset`. Окно попробует взять границы из `MeadowSurfacePainter.source.bounds`, иначе выставить их вручную в профиле.
4. Включить **«Показывать в SceneView»**. В Edit Mode включена независимая имитация ночи (реальное игровое время не изменяется).
5. Настроить `Огоньков / 100 м²`, цвет, размер, эмиссию, скорость, амплитуду, затем **«+ Эллипс»** или **«+ Полигон»**. Плотность области: наследовать, умножить, задать или исключить. Приоритет и мягкий край есть. Границы и перемещение выбранной области видны в SceneView при включённых handles.
6. Поменять пресеты **Off / Low / Medium / High** и ползунок **«FPS ← → графика»**. `Undo/Redo` изменяет экспериментальный профиль как обычный Unity asset, **НЕ** историю `MapEditSession`.
7. Для Play-preview можно явно добавить компонент `FireflyPreviewRenderer` к временному объекту тестовой сцены и указать тот же `FireflyPreviewProfile`. Не сохранять эту сцену в основной ветке.

**Внимание:** профиль самостоятельный: его области сейчас **не сохраняются в данных мира** и не передаются в сетевую игру. Это сознательное ограничение первого запуска, чтобы не менять формат и миграции существующих сохранений до проверки визуала.

### Известные ограничения текущего preview (не скрывать)

- Это промежуточная визуальная проверка, **не полная реализация Issue #85**. Не реализованы запись областей в карту, сетевой перенос, полноценная погодная маска, точный захват преград, surface-aware подсветка и pool реальных источников, дальние агрегаты LOD.
- В Edit Mode при отсутствии загруженной `MapEditSession` берутся результаты `Physics.RaycastNonAlloc`; при отсутствии collider используется `fallbackGroundY`. Поэтому до принятия визуала нужно проверить поверхность и воду на настоящей карте. Слой `groundLayers` в Inspector можно ограничить Terrain.
- Shader ищется через `Shader.Find`; для конечной сборки его придётся гарантированно включить в билд через материал/ссылку asset. Движение эффектов сейчас управляется локальным presentation clock, **не авторитетным игровым временем**.
- Depth fade выключен по умолчанию: при включении проверить доступность URP depth texture. Порядок прозрачностей и вода требуют отдельной проверки.
- За счёт фиксированных точек в сетке при движении камеры эффект обычно устойчив, но ring/cell culling, большие камеры, освещение и пересечения должны быть проверены на GPU и на основной карте.

**Итог:** интеграция в старые системы намеренно отложена; текущий артефакт безопасно тестировать отдельно и при необходимости легко удалить целиком, не затрагивая код игры.
