## Земля и дороги

Семейства: Grass_Base_A, Grass_Dry_A, Grass_Forest_A, DirtGround_A,
DirtPath_A, DirtRoad_A, StonePath_A. У каждого BaseColor, Normal, AO,
Roughness, Height. Размеры и хеши каждого файла в соседнем JSON.

Первый проход: Grass_Base_A для лугов и DirtPath_A для троп; DirtGround_A для
дворов, DirtRoad_A для широких дорог подключать после источника масок.
Сухая трава и лесная подстилка — дополнительные варианты, каменная дорожка —
последующий тип покрытия. В текущем шейдере три текстуры, поэтому семь семейств
не означают семь одновременно семплируемых слоёв. Не занимать слот скалы
каменной дорожкой: это разные поверхности. Отдельной бесшовной скалы в этой
папке нет; на первом тесте допустима существующая цветовая заглушка склона.

Начать с цветовых карт и существующего LC_Terrain. Сначала передать реальные
маски дороги/влажности из данных в mesh: сейчас этого нет. Сохранить все PBR
исходники, но не включать сразу parallax/displacement и дополнительные выборки.
Визуально проверить бесшовность и масштаб: сам перечень файлов их не доказывает.

## Oak Kit: проверка реальных FBX

Blender 4.4.3 повторно импортировал три FBX без сохранения исходников:
LOD0 12068, LOD1 6858, LOD2 3106 треугольников. Каждый содержит один mesh,
два материала (кора/листва), UV0, ненулевые нормали; тангенты вычисляются.
Vertex Colors отсутствуют. Листва — реальная геометрия, 2880/1440/720
треугольников по LOD. Это статическая проверка, не визуальная проверка ветра.

Классификация относительно предпочтительного раздельного контракта:
COMPATIBLE WITH MASK/AUTHORING CHANGE. Практический первый вариант — назначить
LC_StylizedLit коре и LC_Foliage только слоту листвы и проверить общий mesh в
Unity. Если валидатор/анимация требуют раздельных объектов, разделить по
материалам в новом экспортном пакете с общим origin без изменения геометрии.
Не назначать ветер всему дереву. Для общей ветровой поверхности нужна маска R.

Внешний вид коры в Blender: 30% T_Oak_Bark_A_BaseColor + 70% Mat/Bark/Bark_BaseColor,
у существующих Bark BaseColor/Normal UV scale (0.4, 0.45), normal strength 0.28.
Такой граф нельзя считать перенесённым через FBX: подготовить запечённую
совместимую текстуру либо проверенное воспроизведение материала. Листва берёт
Mat/T_Foliage/T_Foliage_BaseColor с alpha и tint linear (0.56, 0.67, 0.40).
Сохранить alpha clip и двусторонность. Палитру модулей проверить отдельно:
её UV не доказывают root-to-tip UV Y, требуемый LC_Grass; автоматически
подключать ветер всей траве Oak Kit нельзя.

Обязательно Unity foliage validator и близкая/дальняя камера, тени, отсутствие
резинового ствола и мерцания. Исходный build_oak_kit.py не запускать.

## Дом, пропсы и стены

Первый мини-посёлок: 3–5 экземпляров House Cottage A, общий колодец, несколько
ящиков/бочек, дрова/дровник, скамейка, забор/калитка, несколько дубов и камней.
Это предложенный размер теста. Не размножать весь декоративный двор v027
целиком у каждого дома. Дом, ограды, украшения и игровые препятствия разделить.
Модули без завершённых материалов не включать по умолчанию.

Имеющиеся LocalHandoffs/candidate-v001 — кандидаты, не утверждённые экспорты:
предыдущий аудит выявил слабые LOD у части модулей. Нужны актуальный экспорт
дома, проверка зависимостей текстур и визуальное сравнение со сборкой v027.

Стены v004: двухметровая секция 3659/1504/408 треугольников. Использовать
прямые жёсткие секции, не модель целого изогнутого периметра. Connections.json
и Textures/material-bindings.json входят в пакет. Башни/ворота — отдельные
структуры. Дефолтный socket clearance 1.5 м в Unity не считать подходящим:
README v004 предупреждает о щелях и фазе размещения. Створки отдельные,
коллизия арки оставляет проход. Геометрические QA не подтверждают runtime docking.

## Размещение и производительность

Сначала выбрать/сформировать плавные поселковые зоны на стадии генерации,
до дорог и scatter. Согласовать макроплан с итоговым рельефом и не перестраивать
его вслед за камерой. Проверять весь footprint, края фундамента и подход ко
входу. Умеренный перепад скрывать допустимым заглублением основания; непригодное
место отклонять. Если этого недостаточно, отдельно добавить ограниченную
автоматическую коррекцию. Не начинать со сложного runtime-терраформинга.

Объекты размещать по ID и детерминированным правилам. Сначала дома/дороги/ворота
и свободные подходы, затем деревья/камни/декор с исключениями. Навигация и
коллизии должны видеть ту же землю; рисунок дорожки не создаёт путь сам по себе.
На возвышениях башни проверяются по собственным ограничениям; на крутых горах
обычные дома запрещены. Пороги уклонов выбрать на тестовом участке и закрепить
в настройках, а не объявлять произвольные числа игровым балансом.

Целевой кадр 60 FPS — около 16.67 мс. Предварительный профиль Low для замеров:
1080p, текстуры до 1024, более ранние LOD, сокращённая трава и дистанция теней,
без дорогих дальних теней/локальных источников. Medium: до 2048 и больше декора.
Это стартовые настройки эксперимента, не внедрённые пресеты и не гарантия FPS.
LOD не решает CPU-стоимость жителей, pathfinding и большого количества объектов:
измерять её отдельно. Не удалять игровые деревья/стены при снижении графики;
менять представление и декоративную плотность, сохраняя одинаковые данные мира.

## Следующий проход

1. Подготовить версионные экспортные пакеты выбранных ассетов; сохранить ID.
2. Подключить луг/тропу и исправить передачу масок, показать маленький участок.
3. Подключить один Oak Kit, один дом и стену; проверить материалы/LOD/масштаб.
4. Собрать мини-деревню по seed на пригодной площадке с проходами к входам.
5. Проверить несколько seed, границы чанков, выгрузку/загрузку и сохранение.
6. Замерить Unity Player: кадры CPU/GPU, память, streaming spikes, лес и деревню
   на ближней/дальней камере; затем наращивать размер карты и 2/8/16 игроков.

Повторить статический аудит можно командой:
`blender --background --factory-startup --python Tools/audit_terrain_starter.py`.
JSON содержит 67 каталогизированных моделей-кандидатов выбранных семейств,
а не приказ импортировать все 67. Полные исходники и исторические версии сохранены.
