## Что пользователь просит

- Понятно сохранять карту и сразу видеть именно её в игре.
- Удобное управление без конкурирующих режимов мыши.
- Дорожки разных будущих типов должны естественно переходить в брод.
- Пологий берег: трава → грунт/песок → мелкая вода, без прямоугольных обрывов.
- Растительность отступает от воды и склонов, плотность меняется естественно.
- Готовые цветы доступны в редакторе и видны сразу после штриха.
- Вода имеет спокойную мелкую рябь, не выглядит полосатой и светящейся ночью.

## Уже исправлено в текущем проходе

- Явный инструмент цветов в разделе «Растительность» и кнопка в Play-панели.
- SceneView получает собственный временный flower preview. Он использует тот же
  MeadowScatterRenderer/MapEditSession, не запускает runtime painter и не пишет source.
- SurfacePaintRasterizer больше не обнуляет R дорожки из-за запрета растительности.
  Это общее правило покрытия, без проверки названия/материала конкретной дорожки.
- Производная маска песка передаётся из MapTerrainPresentation в UV3 terrain mesh.
  LC_Terrain смешивает песок и грунт, сохраняя authored vertex R/G/B и snow/lighting.
- В v2 устранён разрыв высоты на кромке брода; растения исключены со всей ширины
  песчаного склона. V1 height algorithm не заменялся.
- Water material перенастроен: слабее регулярные волны/блики и искажения,
  спокойнее цвета. Пигменты воды/пены и каустика используют общие световые глобалы
  до смешивания отражений/рефракции/тумана. Это первоначальная настройка.

Не повторяйте эти изменения новым параллельным редактором или новым input loop.

## Сначала выполнить только задачу A: сохранение и запуск текущей карты

**Результат для пользователя:** «Сохранить карту», «Сохранить как…»,
«Открыть карту», «Проверить в игре», понятный путь файла и признак несохранённых правок.

Точки входа:

- `Assets/_Game/Editor/MapAuthoringWindow.UI.cs`: DrawMapHeader, SaveDocument,
  OpenDocument, ApplyDocument, CheckpointSession, RestoreWindowSession.
- `Assets/_Game/Editor/MapAuthoringWindow.cs`: PlayState, Connect, RestorePreview.
- `Assets/_Game/Scripts/Research/MeadowSurfacePainter.cs` и его persistence partial:
  runtime Session, ExportJson/LoadJson и SaveEdits/LoadEdits.
- `Assets/_Game/Scripts/World/Runtime/MapEditSession.cs`: ExportMap и delta save.

Важное различие: MapAuthoringDocument — авторская база, MapEditSave — игровые
дельты, привязанные к fingerprint базы. Их нельзя подменять друг другом и нельзя
ослаблять проверку fingerprint ради удобства. Нельзя брать ExportMap с уже
применёнными дельтами как новую базу и затем загружать в неё старый delta save.

Предлагаемая реализация:

1. Запоминать выбранный путь документа; обычное сохранение не открывает диалог
   каждый раз. Dirty сбрасывается только после успешной записи. Ошибка/отмена
   оставляют документ и черновик на месте. Предпочтительна атомарная запись файла.
   Авторский рабочий файл должен уметь хранить неприменённый river draft отдельно
   от runtime-карты (versioned envelope или sidecar). Обычное сохранение не должно
   заставлять применять черновик. Сейчас SaveDocument его блокирует: это реальная
   причина путаницы пользователя. Не включать draft в authoritative rivers молча.
2. «Проверить в игре» передаёт снимок текущего авторского документа через Editor
   bridge. Editor-only код может использовать SessionState для переживания reload;
   runtime получает обычные данные и не ссылается на UnityEditor.
3. Не записывать исходный .asset и не менять сцену автоматически при входе в Play.
   Неприменённый river draft требует явного Apply или отмены запуска, без потери точек.
4. Runtime adapter должен корректно переподключить session, подписчиков и derived
   views. Одного LoadJson(delta) недостаточно для замены авторской базы.
5. Выход из Play возвращает авторский документ. Если в Play редактировали карту,
   предложить явно перенести изменения, сохранить отдельно либо оставить авторский
   документ. Нельзя молча перезаписывать его или терять игровые правки.
6. Существующее «Применить к базе и маске» оставить отдельной дополнительной
   командой. Существующие v1–v5 saves и восстановление окна продолжают работать.

Проверки A: save/open/reopen Unity; отмена файлового диалога и ошибка записи;
edit → Play показывает текущую карту → stop сохраняет исходный документ;
dirty river draft; domain reload; другая база отклоняется; source asset/GUID
не изменяются от простого тестового запуска; Undo lifecycle объяснён пользователю.

После A остановиться с Draft PR и отчётом. Остальные задачи — следующий выбор.

## Следующие отдельные задачи

**B. Общие переходы покрытий и броды.** Сохранять единый контракт coverage для
покрытий, не добавлять if по имени одной дорожки в water shader. Будущий тип пути
может менять материал, но использует общие маски и правила перекрытия.
Начать с SurfacePaintRasterizer, LC_Terrain и MapEditSession.Rivers.
Автоматическое создание брода должно быть явной операцией с ограничением глубины,
уклона и ширины, а не только изменением картинки. Сейчас брод создаётся вручную
MapBankPatch.crossChannel; у него нет связи с ID дорожки. Для автоматизации нужна
такая связь и корректные move/delete/Undo/Redo, с сохранением версии формата.
Тесты: разная ширина пути, оба направления течения, несколько типов покрытий,
наклонный/изогнутый берег, отрицательные координаты, seams и CanTraverse.

**C. Мягкая плотность растений.** Сейчас VegetationAllowed — бинарная проверка,
SandCoverage — плавное покрытие. Нужна общая оценка допустимости/плотности с учётом
берега, уклона и footprint. На краю плотность уменьшать детерминированным hash,
сохраняя stable IDs и одинаковый результат после save/load. Не удалять навсегда
деревья только из-за временной видимости: после удаления реки они должны вернуться.
Потребители: MeadowScatterRenderer, native grass surface mask, MapTreePresentation.
Обновлять затронутые регионы, не сканировать всё население карты каждый кадр.

**D. Отдельный выбор вида цветов.** Готовые модели уже есть в MeadowScatterLibrary.
Пока UI выбирает профиль Flowers и смешивает виды по весам. Для выбора конкретной
группы/вида нужен стабильный ID в данных штриха, обратная совместимость и общий
controller. Не фильтровать старые штрихи по текущему глобальному выбору UI.
Тесты: разные виды рядом, Undo/Redo/save, region rebuild не переставляет дальние цветы.

**E. Производительность рек.** Ранее commit короткой 36м реки занимал ~0.28с на
RTX4070TiSUPER; это CPU commit, не GPU frame. Измерить отдельно ValidateRiver /
MapRiverPath.Nearest / composed height / raster / mesh+collider updates.
Сначала найти причину, затем сокращать повторные запросы и allocations, использовать
индексы и ограниченную очередь derived work. Транзакция данных и Undo остаются атомарны.
Не отправлять Unity API/ScriptableObject в Task.Run. Не сохранять всю карту на dab.

**F. Визуальная доводка воды.** Локально сравнить исходную vendor demo и Main при
одинаковом свете/ракурсе: normal/flow coordinates, мелкая рябь, пена, отражение,
глубина и ночной цвет. Текущая настройка убирает грубую полосатость, но не является
копией референса. Скальные модули и новые природные ассеты сюда не добавлять.
Cloud GPT может подготовить код/параметры и тесты, окончательная оценка — в Unity.
