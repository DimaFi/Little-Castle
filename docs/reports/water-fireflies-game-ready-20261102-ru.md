# Вода и светлячки: единая проверка в Game — 02.11.2026

Продолжение сохранённого performance checkpoint. Пользователь разрешил завершить
текущую интеграцию и подготовить её для самостоятельного просмотра в игре.
PR #88 с дымом только прочитан: его код не установлен, ветка не объединялась.
Объединение дыма требует отдельного решения после пользовательского просмотра.

## Как посмотреть

В открытом World Editor: **Проверить текущую карту в Game… → Запустить текущую
карту + светлячки в Game**. Подготовленный профиль —
`Assets/_Game/Settings/FireflyGameInspection.asset`; материал лежит рядом.
На другом checkout сначала нажать **Подготовить / выбрать профиль Game-теста**.
Для огоньков выбрать ночь, приблизить камеру к зелёному лесу/берегу и подождать
завершения cells. Снег и зимние области по умолчанию подавляют их плотность.
Полная инструкция: [current-map-game-inspection-ru.md](../workflows/current-map-game-inspection-ru.md).

Game получает полный текущий документ до создания runtime presenters. Старая
delta-save поверх изменившейся базы не подгружается. Рельеф, деревья, вода и
светлячки читают одну Session. Неприменённый river draft остаётся в Editor.
Игровое сохранение использует отдельный diagnostic-файл. Выход возвращает
авторский документ; изменения Game автоматически к нему не применяются.
Domain/Scene Reload обязательны; перезагрузка скриптов посреди теста останавливает
тест и сохраняет изоляцию пути Save до уничтожения игровой сцены.

## Реально проверенный игровой запуск

В основном проекте Unity 6000.5.5f1 / DX12 записан 45-секундный прогон текущей
карты: день, ночь у реки, лес, Off, повторное включение и стратегический ракурс.
Точный runtime ExportMap совпал с текущим Editor-документом. После выхода карта,
river draft, Source Surface и scene сохранены побайтно/по соответствующим JSON.
Ошибок в scoped log нет. Off удаляет meshes/material/cache; on подключается снова.

В зелёном лесу выполнена пара On/Off с одной камеры в одном Editor Update.
На кадрах видны отдельные тёплые огоньки; положительная разница содержит 140
тёплых пикселей. За прогон максимум submitted world=166, near=3. Это локальный
пример с сохранёнными настройками, а не гарантия плотности на каждой карте.
Глобальные depth/opaque textures, прочитанные после camera callback, имеют 4×4:
это послерендерное наблюдение, не доказательство отсутствия буферов в shader pass.

## Редактирование и стоимость

Поиск ближайшего сечения сохраняет старый результат, включая ties: сначала
выбирает segment, затем один раз интерполирует frame; консервативные AABB blocks
отсекают лишние кандидаты. Byte-oracle проверяет маску и сохранение road channel.
Предпросмотр переиспользует meshes и presentations, объединяет частые изменения
и обновляет рельеф/растительность/маску порциями. Незавершённый terrain mesh не
публикуется в renderer/collider. Отмена восстанавливает live Session без Undo.
Ранний benchmark: 3,6 с → 1,1 с → 130–153 мс для постановки preview, при прежнем
solver. Последняя оптимизация убирает повторное копирование полной карты на
установившемся жесте: тот же подготовительный путь проверяет live baseline без
Execute, а presentation применяет его к постоянной detached Session.
Итоговый основной benchmark: первый preview 128,5 мс, следующие 76,6/58,6 мс;
полное вычисление очереди заняло 1219 мс CPU за 237 вызовов Editor Tick. Пиковый
полный Tick — 165,4 мс (water Tick до 109,2 мс); MouseUp — 993 мс. Финальная
маска побайтно совпала с синхронным oracle, исходные meshes/presentations сохранены.
Это заметное улучшение исходных 3,6 с, но редкие тяжёлые обновления ещё остаются.

Бюджеты 2 мс рельефа и 2 мс маски кооперативные: refine/upload/collider и отдельная
операция могут выйти за них. Отдельно измеряются полный editor tick, сходимость
очереди и MouseUp. Завершение жеста остаётся синхронным; это не обещание 60 FPS.
Один жест — одна точная Undo/Redo. При восстановлении сцены пересоздаётся только
disposable view, без повторного открытия/замены авторского документа.

## Вода и границы этого этапа

В общем RiverVisualQualityProfile добавлена **refractionBackground** (0–1):
0 сохраняет освещённый пигмент без подмешивания грунта, 1 даёт прежнюю полную
долю фона; default=0,55. Общая HLSL-функция использует настройку для рек и нижнего
перехода водопада. Это настройка visual quality asset, не новое поле v10/v11 карты.
Сравнение с прежним фоном записано при одинаковой карте/камере/фазе воды.
SceneView и Game отличаются правилами буферов URP, окружением и post processing;
полное художественное совпадение разных пользовательских ракурсов не объявляется.
После просмотра пользователь отдельно сообщил о неубедительных отражениях.
Проблема и его локальный референс внесены в
[план отражений](../plans/water-reflections-game-20261102-ru.md); она остаётся открытой.

Верхние/боковые переходы водопада, уменьшение полос и сохраняемые настройки
создания карты остаются отдельным будущим проходом, как запросил пользователь:
[waterfall-transitions-color-controls-20261102-ru.md](../plans/waterfall-transitions-color-controls-20261102-ru.md).
Кувшинки — после модели/LOD и приёмки воды. Issue #85 не закрывается: отдельные
cluster lights и сохранение региональных профилей в самой карте здесь не добавлены.
Текущий эффект даёт emissive glow без Point Light/GameObject на каждого жука.
Player build и большой GPU benchmark в этот проход не выполнялись.
